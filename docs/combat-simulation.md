# 驅動盤評分與戰鬥模擬開發狀態

依使用者最新要求，**先獨立開放驅動盤評分**。`src/assets/combat/scoring-release.json` 設為 `enabled: true`，正式／現行角色卡及合併圖皆可自動評分。完整戰鬥模擬尚未完成，`src/assets/combat/release.json` 仍為 `enabled: false`，模擬工作台與逐項傷害試算入口保持關閉。

評分採主詞條 40%／副詞條 60% 的角色流派權重，單片滿分 100、整套滿分 600，會自動選擇整套分數最高的流派。這是配裝參考分數，不是實戰傷害提升百分比。每片評分維持右上角小字，總分維持總有效詞條旁。權重獨立每六小時更新，先驗證再替換；失敗保留最後可用版本，未知或不合法資料不會猜分。

## 完整戰鬥引擎與 Discord 工作台（2026-10-02）

引擎已升為 `zzz-combat-experimental-5`。下列功能已接入本地模型編譯、Worker 與 Discord 工作台，但**正式遊戲角色模型仍未完成，不能輸出可信的指定隊伍完整 DPS**。原有逐項傷害計算器仍只處理手動選取的項目，與完整事件引擎是兩條不同的計算路徑。

- 固定時間模式預設 90 秒，可設 30–300 秒；擊殺模式以敵人生命值結束，另設最長戰鬥時間。擊殺結果顯示成功率、成功樣本的平均／P10／P90 擊殺時間、有效扣血、過量傷害、護盾吸收及剩餘生命；未擊殺不會假裝在時間上限擊殺。擊殺模式主畫面以擊殺統計為主；匯出中的 meanDps 是每場「有效扣血／實際戰鬥秒數」的平均，若任何場次在 0 秒結束則為空值。
- 戰鬥與動畫使用兩個事件佇列。動畫時間持續前進，所有戰鬥時鐘事件在全域停表期間凍結。增益、資源、冷卻、異常持續／跳傷、失衡和敵人事件能各自指定時鐘；重疊停表取聯集，取消動作會清除該動作尚未執行的停表。每筆事件保存兩種時間。
- 單一目標可設定護盾、按時間或生命比例切換階段、防禦／屬性抗性變化、無敵區段及來襲事件。循環支援動作、切換、等待、條件與有限等待；尚未提供自動最佳化、多目標或空間碰撞模擬。
- 面板編譯器將角色與音擎基礎攻擊先相加，再套攻擊百分比；音擎常駐屬性、驅動盤主副詞條及套裝面板效果只加入一次。戰鬥被動另行套用，不允許被動配置回寫顯示面板。匯入原始配裝會逐項核對官方面板，百分比與回能使用各自的顯示精度。
- v3 方案保存模式、初始資源、敵人範本／自訂值、資料與循環版本。v2 僅安全遷移到固定時間模式。下載方案重新編譯本地模型，絕不執行上傳的程式或信任上傳的已驗證標記。
- Discord 原生介面已可調整模式、時長、目標生命／等級／防禦、六種抗性、失衡、初始資源、角色成長及技能、音擎型號／成長、現有驅動盤主副詞條／強化等級；已驗證音擎和敵人範本支援分頁，並保存原自訂目標設定。沒有可用模型的範本不會出現在可執行清單中。驅動盤目前不新增空槽、不變更套裝或稀有度，主詞條數值需明確填入，尚無已驗證的逐級成長表可自動推算。
- 結果圖片分為總覽、招式明細、第一種子時間軸，支援官方角色／邦布圖示。完整 JSON 報告與 CSV 事件檔保留傷害乘區、歸屬、資源、雙時鐘、生命／護盾結算；報告不含帳號身分資料。完整可重播方案另行匯出。

可重現的圖片預覽：

```sh
npx tsx src/scripts/previewCombatReport.ts
```

輸出 `previews/combat/full-report-{fixed-duration,kill}-{summary,actions,timeline}.png` 及 Discord 樣式 HTML、JSON／CSV。此預覽明確標示三名**合成測試角色**，不使用真實角色立繪包裝測試數字，也不是已登入 Discord 的實際訊息截圖。使用者的真實配裝逐項試算圖片仍使用下節的腳本產生。

### 實戰校準與發布條件

`calibration.ts` 比對獨立錄影觀測與第一種子事件：每擊傷害誤差不超過 1%、整段不超過 5%、命中時間不超過錄影一幀，並要求命中數、傷害類型與可觀察暴擊狀態一致。錄影必須明確選擇戰鬥或動畫時鐘，保存來源 URL、影片 SHA-256、FPS、遊戲／模型版本與方案指紋。僅總傷害相等無法通過；數值通過也不會自動將來源或角色模型標成已驗證。

```sh
npx tsx src/scripts/calibrateCombat.ts path/to/plan-v3.json path/to/capture.json
```

腳本要求方案中的角色已由本地已驗證模型編譯，否則拒絕。校準會先用穩定的 `damageEventId` 合併同一可見傷害的多人貢獻，保留原歸屬明細；同時刻的獨立攻擊仍分開。現有校準單元測試使用獨立手算樣本，**不代表已有真實戰鬥校準通過**。

`coverage.json` 分別追蹤正式實裝清單、角色／邦布機制、裝備、敵人與來源。資料來源候選、已下載數值表和完整戰鬥模型是不同的狀態。`auditCombat.ts` 會列出逐項缺口並核對來源快照雜湊；完整模擬仍須全部模型驗證後開放；此限制不再阻擋獨立的驅動盤評分。

## 真實配裝試算工作台

已新增可在本機操作的**逐項傷害試算**，使用 HoYoLAB 實際角色快照，不依賴合成面板。這是手動條件計算器，不是已完成的自動戰鬥 adapter，也不會解除正式發布條件。

### Discord 圖片與互動

`liveDamageDiscord.ts` 已接入隊伍卡的「逐項傷害試算」入口與既有 `zcombat:` 互動路由，沿用完整戰鬥模擬的發布條件，未隨驅動盤評分上線。介面使用 Discord 原生選單、按鈕及表單，並以 `liveDamageRender.ts` 產生 1000×850 PNG 附件。圖片使用專案內的官方角色立繪／頭像、屬性／技能圖示、音擎和驅動盤套裝資源；圖片更新時移除上一張附件。

可切換角色和招式、勾選條件增益、設定層數／命中次數／敵人防禦／全屬性抗性／失衡倍率，並加入最多 100 個手動傷害項目。每項保留加入時的條件，敵人設定共用；合計顯示三人傷害貢獻，並可清空或匯出完整計算與來源。工作階段綁定操作者、30 分鐘閒置到期，過期修訂及同時點擊不會覆寫新結果。匯出不包含 Discord ID、UID 或 Cookie。

離線預覽直接使用相同訊息產生函式，**沒有登入 Discord 或傳送訊息**：


產出 `previews/combat/discord-damage-{single,team}.html` 和圖片附件；`discord-message-{single,team,mobile}.png` 是瀏覽器擷取的 Discord 樣式本機預覽。範例次數是手動指定的餘燼 ×1、愛麗絲強擊 ×2、蕾米埃爾普攻第一段 ×1，不代表已驗證的實戰循環。原生介面目前為繁體中文，正式 Discord 客戶端的實際點擊驗收仍待發布前進行。

新增 `combatLiveDiscord.test.ts` 驗證圖片附件與元件限制、原生入口及路由、條件快照合計、目標修改、舊修訂／非擁有者拒絕、匯出資料及發布條件；與既有工作台、基礎設施和真實計算器共 4 組 26 項測試通過。

### 本機網頁工作台

```sh
node --import tsx src/scripts/liveCombatCalculator.ts previews/combat/yeci-team-live-data.json 8788
```

開啟 `http://127.0.0.1:8788/`。可選擇三人的已支援倍率段、餘燼、獨立強擊／極性強擊及單次灼燒；調整目標防禦、對應屬性抗性、失衡與條件增益。畫面顯示未暴擊、暴擊、期望、各乘區與生效增益，能把傷害項目加入手動循環並匯出 JSON。每項循環保存加入當時的增益設定；改動設定會使先前結果與匯出失效，非同步舊回應不會蓋掉新設定。

目前範圍是 60 級蕾米埃爾 0–2 影、愛麗絲 0 影、柏妮思 0 影（潛能覺醒 0–6），以及此回歸配裝中的空羽復歸之詩 1 階、淬鋒鉗刺 1 階、嵌合編譯器 2 階與套裝。其他音擎／精煉、四件效果或超出範圍的影畫會明確拒絕，不會當成沒有被動。技能倍率使用匯入角色的實際技能等級，混合屬性總倍率、持續噴射與未取得的覺醒新招式不提供猜測拆分。

已計入的效果：

- 將官方顯示面板與戰鬥增益分開，音擎主／副屬性及二件效果不重複加入。補入面板未包含的空羽復歸之詩精通、嵌合編譯器基於基礎攻擊力的增幅、混沌爵士四件常駐火／電增傷。
- 蕾米埃爾隊伍入場攻擊、相變時流增傷、專武觸發增傷、一影對隊友異常增傷、二影對異常傷害的防禦忽視；後三者依使用者指定的生效條件計算。未把異化／耀變視為已建模。
- 愛麗絲掌控轉精通、淬鋒鉗刺層數、獠牙重金屬條件增傷；強擊和極性強擊僅計單一角色貢獻的原始異常傷害。
- 柏妮思餘燼倍率與精通增傷、各級潛能覺醒的回能轉掌控／增傷與觸發間隔、嵌合編譯器層數、混沌爵士按招式類型生效的後場／換入餘效。面板匯入與 `BuildSpec` 現在保留覺醒等級，啟用覺醒但缺少等級時拒絕匯入。

傷害公式的 60 級防禦基數 794、異常等級倍率 2，以及強擊／灼燒基礎倍率以固定版本 [ZSim Calculator](https://github.com/ZSim-Dev/ZSim/blob/e248e9f149a6b889290579d8e673e132be9bde31/zsim/sim_progress/ScheduledEvent/Calculator.py)、[CalAnomaly](https://github.com/ZSim-Dev/ZSim/blob/e248e9f149a6b889290579d8e673e132be9bde31/zsim/sim_progress/ScheduledEvent/CalAnomaly.py) 核對。技能與裝備效果取自官方技能表及此次官方角色 API 回應。尚未以遊戲錄影逐筆驗證實戰傷害。

**手動循環只加總選定項目，不檢查動作時間、能量、冷卻或增益持續時間，也不自動產生異常。** 未計異化、耀變、紊亂、異常貢獻分攤及愛麗絲追加傷害。只有使用者明確填入時長才產生 `modeledDps`，畫面標記為「僅計入項目／秒」，`completeSimulation` 永遠為 `false`；不提供虛構的完整隊伍 DPS 或 P10/P90。敵人初始值是自訂中性目標，不代表任何關卡敵人。

本機服務只綁定 loopback，使用記憶體快照，API 傳出經白名單整理的角色資料，不傳 Cookie、Discord ID 或遊戲 UID。需要工作台當次權杖才能讀取 API，不開放靜態目錄或跨來源存取。`tests/fixtures/liveCombat.json` 只保留數值回歸所需的角色與配裝欄位。

此版本已通過 TypeScript 建置、相關 ESLint 與 8 組共 59 項測試（其中新增 13 項真實配裝計算／本機服務回歸）。實際瀏覽器檢查涵蓋三人循環加總、改動敵人後重新計算、無效次數、匯出 JSON 與 320／736／1200 像素版面。數值仍受官方面板顯示精度影響；測試驗證公式與程式行為，不代表已完成遊戲逐幀驗收。

- 特殊異常可用獨立狀態識別與同屬性異常結算紊亂，不清除自然異常積蓄。這是極性強擊所需的引擎能力，**尚未完成極性強擊的完整快照與影畫適配**。

以上是可組合的機制實作，**不是三名角色的完整模型**，目前沒有將三人加入正式 adapter。仍缺逐次命中／取消／停表、異常積蓄量與內置冷卻校準、燃點與灼傷的完整狀態轉移、劍儀、流明積蓄點／異化／相變時流／耀變，以及音擎、套裝、影畫和實戰數值核對。官方技能倍率表不提供全部這些資料，不能據此捏造一組隊伍 DPS。

**目前沒有任何正式遊戲角色或邦布註冊為已完成的戰鬥 adapter。** 合成案例測試只能證明引擎對該案例的行為，不能證明實際角色的總傷害正確。

## 計算與介面契約

百分比一律使用百分點：24 表示 24%。`normalizeDiscStat` 將顯示文字轉成數字，固定攻擊與攻擊百分比分開。未知詞條、缺少強化等級或不合法詞條不會自動當成零。

`scoreCharacter` 接受角色回應、不可變權重快照及流派；自動模式選整套分數最高的設定。分數保留精度、顯示一位小數；空槽計零，無法解析的槽位會阻止完整總評。

`BuildSpec` 是配裝選擇；`ActorModel.compile` 是受版本管理的本地 adapter；`BuildSnapshot` 是編譯後的面板、技能與資源。Discord 匯入配裝不可上傳程式碼，必須重新經 adapter 編譯。現在 adapter 清單為空，因此不會把缺漏效果當成不存在。

`SimulationScenario` 固定資料版本、1–3 名角色、可選邦布、敵人、循環、30–300 秒及種子。預設工作台為固定 90 秒、100 次模擬；擊殺模式未指定上限時預設 300 秒。固定模式 DPS 使用指定戰鬥時長；擊殺模式主畫面改報成功率與擊殺時間，匯出另保存逐場有效 DPS 平均，分母為各場實際戰鬥時間。每角色 DPS 因未保存逐場分母而不提供估算。結果區分多次平均與第一個種子的詳細事件／失衡區段。

時間以整數毫秒排程，並不表示來源已達毫秒精準度。同時刻依恢復／到期、敵方事件、命中、邦布決策、玩家決策排序，再以序號穩定排序。區間右端不含模擬結束時間。必須用實測資料驗證這些排序能否覆蓋各角色。

Worker 預設同時 2 個、最多 10 項等待／執行中工作、執行逾時 30 秒；取消和逾時不回傳不完整總傷害。正式互動不會在主執行緒跑模擬。
