# Auto Mimo 與設定介面

在 `/settings` 的 Auto Mimo 項目按「設定」開啟原本的私人設定面板。也可使用 `/setup` 快速管理全部已綁定 HoYoLAB 帳號。自動執行預設關閉，兌換獎勵預設只有菲林，首次設定預設私訊通知且不提及。選擇領獎 UID、獎勵、排序與通知位置後，再按啟用。通知可選關閉、私訊或目前伺服器的頻道。

## 單項設定

提醒、新聞訂閱、一般設定、Auto Mimo、模擬調頻設定皆採「總覽 → 修改一項 → 儲存 → 總覽」。儲存立即生效；完成僅關閉面板。取消只放棄目前項目的草稿。相同項目被其他面板修改時，拒絕覆寫；其他項目的變更保留。

設定圖片使用既有遊戲素材；展示樣式圖片是合成示意，沒有真實使用者資料。所有新增圖片沿用專案既有各語言遊戲字體，不另外套用其他字體。圖片缺失仍可操作文字選單。

## 執行範圍

- 只完成已核對的瀏覽／點擊類任務（task_type 1、2、4、10），並領取官方狀態為已完成的任務積分。未知類型、未完成的遊戲／社群任務不執行。
- 支援的獎勵可多選；順序可調整。較高順位積分不足或缺貨時保留積分；確認個人額度已用完才往下一順位。商品消失時不推測已結束。
- 同類型以每積分獎勵數量排序，在可負擔且有庫存的選項中選取。未知數量不自行補造。
- 每個 Hoyolab 帳號綁定一個領獎 UID，不能由兩個 Discord 使用者重複排程同一帳號。
- 僅主叢集排程，每分鐘檢查到期項目，各帳號原則每小時執行。關閉後不再進行新的自動操作。

## 交易與兌換

購買前先寫入 SQLite 購買意圖，成功取得的私人兌換碼寫入獨立 Mimo 表，不混入公開兌換碼清單。購買網路錯誤、回應無法解析或程序中斷時，先比對官方積分紀錄；無法唯一核對即停止新購買，不盲目重試。

取得兌換碼但遊戲兌換未完成時，保留碼與購買時的 UID，稍後續試；更換設定中的 UID 不會改動已購買碼的領獎帳號。私人面板可查看待兌換碼；公開通知與結果圖不包含私人碼。Mimo 與公開自動兌換共用 UID 的持久化冷卻時間。

登入失效會嘗試既有憑證更新；無法恢復時只停用受影響帳號。只有結果或新的錯誤需要通知，等待積分／庫存不重複提醒。通知失敗不會觸發重新購買。頻道永久失效時停用該通知目的地。

## 結果圖

手動、自動與 Mimo 兌換沿用同一套圖卡：獎勵圖示、依使用者設定語言呈現的已知獎勵名稱、真實數量、UID、兌換狀態。未知獎勵保留來源文字，明細缺失明確表示不可用。僅實際兌換成功標示成功；已兌換、待處理與失敗分開。同一兌換碼的多項獎勵歸在同一組，狀態僅顯示一次。獎勵採三欄置中的小格排版，超過六筆獎勵分頁，超過十張圖片分批發送；繪圖失敗提供完整文字附件。

七種語言為英文、繁中、簡中、日文、韓文、法文、越南文。Mimo 圖另外顯示本輪取得／消耗積分與餘額。

## 驗證與上線

核心測試使用記憶體 SQLite 與模擬官方回應，不消耗真實積分、不發送 Discord 訊息。執行 `node --import tsx previews/auto-mimo/render.ts` 可重建七語系示意圖，UID 為合成資料。

本次實作沒有重啟 PM2，也沒有進行真實購買。部署時需依既有流程編譯、註冊新指令並重啟 bot；設定預設關閉，需使用者明確啟用後才執行。首次啟用應觀察官方任務／商品回應與私人結果紀錄。

獎勵備援圖示取自官方 HoYoWiki，圖片與條目來源記錄於 `src/assets/images/zzz/rewards/sources.json`。已內建菲林、丁尼、三種調查員記錄、音擎能源模組／蓄電池及以太鍍劑，網路圖片缺失時使用本地圖示。
