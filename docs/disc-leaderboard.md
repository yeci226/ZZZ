# 驅動盤排行榜

入口為 `/leaderboard`（繁中 `/排行榜`）以及角色卡的「查看排行榜」按鈕。按角色分榜，可切換全球／本伺服器，每頁 10 人，圖片包含遊戲內暱稱、Discord 名稱與頭像、遊戲 UID、角色外觀、分數、等級及更新時間。圖片、指令、操作按鈕、設定及錯誤提示提供七語系。

遊戲暱稱由已綁定帳號讀取，依上榜配裝的實際 UID 配對；多帳號採最高分的那個帳號，不使用綁定清單第一筆。相容新舊帳號儲存格式，這次讀取不進行資料遷移；暱稱缺少時仍顯示 Discord 名稱與 UID。底部「我的排名」為獨立個人卡，包含大型名次、角色立繪、頭像、身分、有效詞條數與分數評級；不在當頁的玩家也會顯示。尚未上榜與已退出提供不同提示。

訊息底部的角色選單可直接切換排行榜，選單內含上一頁／下一頁角色，沿用 `/profile` 的 25 個選項分頁規則。切換角色保留全球／伺服器範圍並回到名次第 1 頁；單純瀏覽選单頁不重繪圖片、不更改名次頁，也不收錄資料。

有玩家的頁面另提供「選擇玩家，查看上榜角色配裝」選單，最多列出當頁 10 人，含遊戲暱稱、Discord 名稱、UID 及分數。任何人都可選擇，透過私人回覆查看該上榜 UID 的同一名角色，沿用查看者的 `/profile` 圖卡外觀設定，公開排行榜維持原狀。角色卡即時查詢目前配裝，內容會註明排行榜仍以上次同步為準；查看本身不更新排名、不遷移帳號資料。載入前後皆重新確認該玩家仍參與、符合排行範圍且上榜 UID 未變更，退出、解除綁定或換成其他帳號上榜時會提示重新整理。登入失效或資料讀取失敗以私人提示回覆，不切換至其他帳號。

排行榜訊息的按鈕與角色選單開放所有使用者操作。翻頁、重新整理、切換角色或範圍會更新同一則訊息，圖片中的「我的排名」以此次點擊者為準；單純瀏覽角色選單頁保留原圖。「退出全部排行」與「重新加入」只變更實際點擊者的參與設定，不使用訊息原開啟者的身分。私人設定面板仍只允許本人操作。

選單的角色選項使用與 `/profile` 相同的屬性 emoji，包含烈霜、玄墨、淬鋒等特殊屬性。屬性資料存於 `src/assets/disc-leaderboard-elements.json`，取自官方 Wiki／HoYoLAB 角色資料；翻頁不會遺失圖示。排行榜及同步狀態的 `content` 提示使用 `-#` 小字，與全機器人的訊息發送格式一致，圖片與按鈕標籤維持原樣。

指令明確支援伺服器安裝與使用者安裝，以及伺服器、機器人私訊和其他私訊情境。繁中客戶端顯示名稱為 `/排行榜`。如果 Discord API 已有全域指令，但特定使用者看不到，仍需檢查實際安裝位置、伺服器整合權限或客戶端指令清單，不能僅由全域註冊狀態判定使用者端已可見。

針對需要立即同步指令清單的個別伺服器，可在 `data/zzz-guild-command-overrides.json` 設定 `schemaVersion: 1` 與 `registrations: [{ applicationId, guildId, commands: ["leaderboard"] }]`。啟動時只對符合目前機器人 application ID 的指定伺服器逐筆更新指令，沿用已載入指令的選項及翻譯，不覆蓋該伺服器其他指令。伺服器版本省略僅適用全域指令的安裝類型與私訊情境欄位。

## 收錄及排名

- 使用自己的 `/profile` 時，主卡顯示後會在背景同步該遊戲帳號全部已擁有角色，不限公開展示角色，也不用逐一點選。指定另一個綁定帳號時同步的是該帳號，不會掃描玩家其他綁定帳號。完成或部分失敗會在原訊息顯示提示。
- 查詢自己的單一角色或隊伍也會即時更新對應配裝；看別人的角色、開啟排行榜或單純渲染圖片不會收錄。
- 全部六片驅動盤可評分才符合資格；最新不完整或無法評分的配裝會下榜。API 失敗保留原資料。較舊請求晚完成不會覆蓋新配裝。
- 總分滿分 600，依顯示的一位小數排序；同分並列（1、1、3）。每位 Discord 玩家一席，多帳號取各帳號最新配裝中的最高分。同 UID 由第一個自行查詢的玩家收錄，避免重複佔位。
- 伺服器榜包含曾在該伺服器同步自己 `/profile` 或查詢該角色的玩家，不掃描伺服器成員。同帳號在另一個伺服器查詢時，即使正在同步或處於冷卻，也會補上該伺服器的關聯。
- 排行榜或設定可退出全部排行；之後查詢不會自動重新加入。重新加入顯示保留的配裝，玩家可再次查詢更新。解绑移除該帳號的排行資料。

## 儲存及維運

`data/zzz-disc-leaderboard.sqlite` 使用 WAL、外鍵與交易，支援五個分片共用。可用 `ZZZ_DISC_LEADERBOARD_DB` 指定測試路徑。只儲存排行身分、公開圖片來源、評分必要的裝備欄位、伺服器關聯與參與設定；不儲存 cookie 或客戶端物件。排行圖片公開上榜配裝所屬帳號的遊戲暱稱與 UID，並保留 Discord 名稱。

優先使用 HoYoLAB 養成指南的 `POST /event/nap_cultivate_tool/user/batch_avatar_detail_v2`，每批最多 10 名角色，使用回傳頂層 `equip` 的目前配裝，排除推薦方案與未解鎖角色。先以既有 cookie 完成 badge 授權，取得的活動 token 僅保留在當次同步記憶體，不寫入資料庫。外觀沿用 `/avatar/basic` 的目前皮膚 ID，轉成同皮膚的官方直式圖片。

若活動授權或批次查詢不可用，或回應缺少部分角色，僅針對尚未取得的角色回退至原本 `GET /avatar/info` 單角色端點。每個分片依序處理背景同步，批次／角色請求間隔 250 ms，共用資料庫租約防止同 UID 跨分片重複同步。成功後冷卻 60 秒，部分失敗後 15 秒可重試。活動請求逾時 8 秒，SDK 單角色最多等候 12 秒；連續 3 次單角色失敗或整體超過 120 秒就保留已完成進度並停止。退出排行或解除綁定會撤銷執行中的租約。沒有取得有效配裝回應的角色保留舊資料，明確回傳空配裝則依失格規則下榜。

批次規格交叉參考 [genshin.py 的 ZZZ 客戶端](https://github.com/seriaati/genshin.py/blob/master/genshin/client/components/chronicle/zzz.py)，實測同帳號 41 名角色的批次與單角色分數完全一致，41 張目前外觀的直式來源也一致。

權重更新先在背景批次重算，再於交易中同時發佈全榜與版本；期間保留上一份完整榜單，新查詢一律使用資料庫目前發佈的版本。發佈前會納入重算期間新增或修改的配裝，避免混用版本。

外觀優先使用 API 回傳的角色立繪，沒有直式圖片時才由目前方形圖片對應同一皮膚；不以「已解鎖」推論目前外觀。公開名稱翻譯來自 HoYoLAB 角色資料與官方 HoYoWiki；缺少皮膚譯名時顯示當地語言的「角色立繪」。

不將預覽名次或測試玩家寫入正式資料庫，也不批次回填已綁定帳號。部署後由玩家自行查詢累積榜單。

## 驗證

測試涵蓋本人收錄、退出與重加入、共享排行榜跨使用者操作、退出只影響點擊者、私人設定所有權、帳號去重、降分、失格、同分、分頁、伺服器隔離、解除綁定及延遲回應、跨連線與重啟保存、權重交易更新、七語系圖片與 Discord payload。`previews/disc-leaderboard/live-smoke` 為隔離記憶體資料庫產生的驗證圖片，沒有發佈至 Discord。
