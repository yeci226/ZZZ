# 調頻紀錄圖改版：海報風格、全頻道首頁、S 牆、依版本

日期：2026-11-18
狀態：使用者已確認（2026-11-18），待寫實作計畫

原本規劃四項工作，這份文件涵蓋其中兩項：調頻圖改版，以及接官方新 API（`nap_gacha_record`）。使用者決定直接用新 API 當資料來源，所以兩項合併。另外兩項各自另開設計：抽卡排行榜、用真實保底做抽卡規劃。

## 為什麼要改

官方 HoYoLAB 推出了調頻統計工具，玩家會拿它和 bot 比。對照之後，bot 現在的 `/調頻 紀錄` 有四個問題：

1. 一頁只放得下 10 個 S。每張 S 卡用數字、顏色、長條三種方式畫同一個抽數，名字又和頭像重複。
2. 一進去只看得到單一頻道，要切 6 次才知道全貌。
3. 最重要的「目前墊幾抽、是不是大保底」排在數據列最右邊，全圖最大的字卻是卡池名。
4. header 只是一條裁到剩眼睛的橫幅，沒有記憶點。

## 目標

- 進來的第一張圖就看得到六個頻道的狀態。
- 頻道頁一頁能看 34 個 S。
- 圖有辨識度，玩家願意貼出來。
- 可以依版本看每一期花了幾抽、拿到什麼。

## 不做

- 不用模擬調頻的歷史卡池表替手動匯入的帳號補舊卡池資料。
- 不做排行榜、不做抽卡規劃。首頁也不預留它們的按鈕。
- 不加「歪」標籤，資料不明的 S 也不加「?」角標。
- 不做官方的「全部／已結束」切換。
- 不做深色主題，不保留舊樣式，不加新舊切換設定。
- 不改匯入流程、隱私設定、每週封存。

## 做壞了的樣子

- 圖的高度超過寬度的 1.1 倍（Discord 會把高圖縮小）。
- 要翻頁才看得到目前墊抽。
- 同一個頻道的目前墊抽，在不同畫面顯示不同數字。
- 缺立繪或缺資料時丟錯，或畫出空白的大塊。

## 限制

- 輸出是一張靜態 PNG 加 Discord 元件，元件最多 5 列。
- 寬 1000、輸出 2 倍解析度，維持現狀。
- 七種語言（tw、cn、jp、kr、fr、vi、en）。
- 全身立繪本機只有 45 個 S 角色中的 18 個（`src/assets/images/agents/{id}.webp`）。
- 封存紀錄裡，卡池的期間和 UP 名單只來自 HoYoLAB 的 `gacha_calendar`，在同步當下寫入。日曆沒涵蓋到的舊卡池，紀錄會落到「未分類」，那些 S 也判斷不出是不是 UP。官方綁定的帳號改用新 API 解決，見下一節。
- 這台開發機沒有任何帳號的登入資料，正式環境在另一台機器上。

## 資料來源：官方新 API

使用者決定：S 的清單、UP 判斷、分期和統計直接用官方新 API，不用模擬調頻的歷史卡池表去比對時間。

### 已驗證（2026-11-18，用使用者自己的帳號在正式環境實測）

探測腳本是 `src/scripts/probeGachaRecordApi.ts`，只讀取、不寫入 bot 的資料庫。之後 API 改版時可以再跑一次。

- 位置：`https://sg-act-public-api.hoyolab.com/event/nap_gacha_record`
- 都是 GET，查詢參數 `uid`、`region`、`lang`。**只帶 HoYoLAB cookie 就能用**，不需要活動登入，也不需要 DS 簽章。沒登入時回 `retcode: -100`。
- 歷史涵蓋到 1.0（最早一筆是 2024-07-04），六個頻道都有資料。各頻道卡池裡的 S 加起來，和 `type_stats` 的 `s_count` 完全相符。
- 首次完整抓取共 19 個請求。

| 端點 | 參數 | 回傳 |
|---|---|---|
| `/api/zzz/index` | 無 | `total_gacha_count`、`total_s_count`、`cur_ver`、`cur_tickets[]`、`type_stats[]` |
| `/api/zzz/cur_pool_stat` | `gacha_type` | `list[]`：目前版本的各期卡池 |
| `/api/zzz/hist_pool_stat` | `gacha_type`、`vers`（逗號分隔，一次最多 8 個） | `list[]`：每個版本一筆 |

`gacha_type` 查詢時用數值：常駐 1、獨家 2、音擎 3、邦布 5、獨家重映 102、音擎迴響 103。回傳裡是字串，例如 `GACHA_TYPE_CHARACTER_UP`。數字欄位多半是字串，要自己轉。

**`type_stats[]`**，每個頻道一筆：

| 欄位 | 意思 |
|---|---|
| `total_count` | 該頻道總抽數 |
| `s_count` | S 數量 |
| `up_count` | UP 的 S 數量。常駐恆為 0，邦布等於 `s_count` |
| `avr_up_count` | `total_count` 除以 `up_count`；常駐是除以 `s_count` |
| `next_s_cur_times` | 目前墊抽 |
| `new_s_max_times` | 距硬保底還有幾抽。兩者相加就是硬保底（90 或 80） |
| `has_data_vers` | 有抽卡紀錄的版本，新到舊。包含有抽但沒出 S 的版本 |

**`cur_tickets[]`**：`GACHA_TICKET_TYPE_RECHARGE_MONOCHROME`（菲林底片）、`POLYCHROME`、`ENCRYPTED_MASTER_TAPE`、`MASTER_TAPE`、`BOOPON`，各帶 `ticket_cnt`。

**卡池一筆**：`gacha_type`、`gacha_state`（`GACHA_STATE_IN_PROGRESS`、`GACHA_STATE_ENDED`）、`version`、`start_ts`、`end_ts`、`cur_item_list`（該期 UP）、`cur_records`（該期抽到的 S，新到舊）。

- `cur_pool_stat` 回傳目前版本的每一期，有起訖時間和 UP 名單。邦布頻道只有一筆且沒有時間；常駐頻道回空清單。
- `hist_pool_stat` **每個版本只有一筆**，不分上下半，`start_ts`、`end_ts` 是 0，`cur_item_list` 是空的。該版本沒出 S 就沒有這一筆。目前版本不在這裡，要從 `cur_pool_stat` 拿。
- **沒有每一期或每個版本各抽了幾抽的數字。**

**S 一筆**：

| 欄位 | 意思 |
|---|---|
| `item_id`、`name`、`icon`、`item_type`、`rarity` | 物品。`name` 跟著 `lang` 變 |
| `count` | 這個 S 出在第幾抽（保底位置） |
| `sort` | 這個 S 是該頻道的第幾抽（從頭累計）。最新一筆的 `sort` 加上目前墊抽等於 `total_count` |
| `is_up` | 是不是 UP。常駐恆為 false，邦布恆為 true |
| `up_tag` | `UP_TAG_NEW` 或 `UP_TAG_NONE`，只在目前版本的新角色上看到 `NEW` |
| `record_time` | 抽到的時間，Unix 秒 |

### 怎麼用

- **官方綁定的帳號**：首頁、頻道頁狀態區、S 牆、依版本都用新 API 的資料。保底週期要看 A 的位置，新 API 沒有逐抽資料，繼續用封存的逐抽紀錄。
- **只有手動或 rng.moe 匯入的帳號**：全部照舊用封存紀錄算。日曆沒涵蓋的舊卡池會落在「未分類」，那些 S 沒有 UP 角標。這是已知的落差，不另外補。
- 兩種來源先轉成同一種內部格式再交給繪圖，繪圖不需要知道資料從哪來。格式至少包含：每個頻道的總抽數、S 數、UP 數、每個 UP 平均、目前墊抽、硬保底；每個 S 的物品、保底位置、是否 UP、時間、所屬版本和卡池。
- **儲存**：新 API 的回傳存進現有的封存資料庫（`zzz-gacha-archive.sqlite`），新開資料表。已結束的版本不會再變，存過就不重抓；每次只抓總覽、目前卡池、目前版本，以及還沒存過的版本。
- **時機**：和現有的官方同步一起，在開啟 `/調頻 紀錄` 時做。請求之間沿用現有的 250 ms 間隔。
- **失敗時**：改用封存紀錄算出來的資料畫圖，並把畫面標成同步失敗，不讓指令失敗。
- 官方工具有同步延遲，所以新 API 的數字和逐抽紀錄可能差幾抽。保底週期以逐抽紀錄為準，其他畫面以新 API 為準，同一個畫面內不混用。

## 考慮過的做法

### 版面

| | 做法 | 結果 |
|---|---|---|
| A | 新首頁放全頻道狀態，選頻道後進 S 牆，保底週期降為次要畫面 | **採用** |
| B | 保留現有兩個畫面，S 清單改 5 欄 20 個，全頻道做成下拉的一個選項 | 預設仍是單一頻道，兩個畫面重複的問題還在 |
| C | 頻道頁改成每期卡池花費的時間軸 | 手動匯入的資料多半落到「未分類」；其中「依版本」的概念併入 A 當成一個畫面 |

| | 做法 | 結果 |

## 畫面

共四個畫面：首頁、S 牆、依版本、保底週期。後三個屬於「頻道頁」，共用左側面板和上方的狀態區。

### 共用：左側海報面板

寬 264，佔滿整張圖的高度，右邊緣是一條向左下傾斜的墨色斜線。

- 底色是主角的屬性色，疊一層淡的白色斜紋。
- 主角的全身立繪置中，從頂端往下畫，下半部被深色漸層蓋住。
- 漸層上由上到下：白底小標籤、傾斜的白色粗體大標題、分隔線、玩家名稱、UID。

| 畫面 | 大標題 | 小標籤 |
|---|---|---|
| 首頁 | 調頻總覽 | 全頻道 |
| 頻道頁 | 頻道名稱 | 全部紀錄；保底週期選了單期卡池時是卡池名稱 |

**主角怎麼選：**

| 情況 | 主角 |
|---|---|
| 首頁 | 所有頻道中最新抽到的 S 角色 |
| 保底週期選了單期卡池 | 該卡池的 S 級 UP；UP 是音擎時用它的專屬角色 |
| 全部紀錄 | 該頻道最新的 UP S；沒有 UP 資料時用最新的 S |
| 常駐頻道 | 最新的 S；是音擎時用它的專屬角色 |
| 邦布頻道 | 最新的 S 邦布，用邦布圖 |

**缺圖時依序退回：**

1. 全身立繪。
2. 橫式半身圖（`src/assets/gacha-simulation/ui/characters/{id}.png`），只佔面板上半部，以 catalog 的 `crop` 臉部位置置中，下緣漸層融入屬性色。
3. 音擎或邦布的方形圖示，放大後略微旋轉、加陰影。
4. 只有屬性色和斜紋。

屬性色沿用 `safeAccent` 加 `getPaperAccent`。屬性從卡池的 `upItems.elementType` 取，沒有時查 `src/assets/disc-leaderboard-elements.json`，再沒有就用預設的 `#de493e`。

```
│         │ 獨家頻道   78/90 [大保底]        [S][S][S][S] │
│         │ 2,434 抽·45 個 S  ████████░░      39 77 77 75 │
│         │ 獨家重映                             尚無紀錄 │
│ 全頻道  │ 音擎頻道    6/80 [小保底]        [S][S][S][S] │
│ 調頻總覽│ 音擎迴響                             尚無紀錄 │

```

- **票券列**：只在官方來源且有票券資料時顯示，資料來自新 API 的 `cur_tickets`。顯示菲林底片、菲林、加密母帶、原裝母帶、邦布券五格（使用者決定顯示菲林底片）。右側多一格「限定頻道可抽」，算法是菲林除以 160 取整，加上加密母帶數量，不計菲林底片。菲林底片的圖示從 `src/assets/images/zzz/official-record/` 現有的圖裡找，沒有合適的就用新 API 回傳或官方素材補一張。
- **六個頻道固定順序**，各一列。沒有紀錄的頻道壓成半高，只寫頻道名和「尚無紀錄」，不消失。
- **有紀錄的列**由左到右：
  - 頻道名稱，下方是總抽數和 S 數量。
  - 目前墊抽大數字加硬保底、進度條。限定頻道加「大保底」或「小保底」標籤：該頻道最新的 S 不是 UP 就是大保底，是 UP 就是小保底，還沒有 S 或判斷不出來時不畫。
  - 最近 4 個 S：頭像、UP 角標、抽數色塊。
- 頁尾寫紀錄起始月份和更新時間。同步失敗時改成紅字的同步失敗訊息。

### 頻道頁共用的狀態區

在右側上方，三個頻道畫面都有，每一頁都顯示。

- **墊抽卡**，一行：「目前墊抽」標籤、大數字加硬保底、進度條、大小保底標籤，右上角寫「距硬保底 N 抽」。墊抽是推算的時候，標籤後面加「推算」。
- **數據格**：

| 頻道 | 顯示 |
|---|---|
| 限定（獨家、重映、音擎、迴響） | 總抽數、平均出 S、UP / S、每個 UP 平均 |
| 常駐、邦布 | 總抽數、平均出 S、S 數量 |

沒有值的格子顯示「—」。

### S 牆

7 欄，新到舊。每格是一張小卡：頭像、右上角 UP 角標、下方抽數色塊。

- 第 1 頁的第一格是目前墊抽：虛線框加「?」，下方是目前墊抽的色塊。只有在看的是頻道最新紀錄時才出現（沿用現有的 `openCycleIsLive` 判斷）。
- 每頁 35 格，所以第 1 頁是「?」加 34 個 S，之後每頁 35 個。
- 至少畫 3 列的高度，新玩家的圖才不會太扁。
- 沒有 S 時顯示空狀態文字。
- S 牆固定顯示該頻道的全部紀錄，不提供單期篩選。要看某一期抽到什麼，用「依版本」。

### 依版本

把同一個頻道的 S 依版本分段，新到舊。

```
3.3  賽維里安／諾姆    11/11–12/01  [進行中]         沒出 S
3.3  菲歐妮／維琳娜    10/21–11/11                4 個 S · 4 UP
[菲歐妮 76 UP] [維琳娜 77 UP] […] […]
3.2                                               沒出 S
3.1                                               4 個 S · 3 UP
[蕾米埃爾 30 UP] [柳 18] [蕾米埃爾 65 UP] [蕾米埃爾 76 UP]
```

- 每段一行標題，下方是該段的 S，格子和 S 牆相同，7 欄。
- **目前版本**依 `cur_pool_stat` 分成各期，標題有 UP 名稱和起訖日期，開放中的那一期加「進行中」標籤。
- **過去的版本**每個版本一段，標題只有版本號。新 API 不提供舊版本的分期、日期和 UP 名單，所以不顯示。
- 標題右側寫 S 數量；限定頻道再加 UP 數量。新 API 沒有每個版本各抽了幾抽的數字，所以不顯示抽數。
- `has_data_vers` 裡有、但沒出 S 的版本，只畫標題行並寫「沒出 S」。
- 這個畫面不顯示卡池選單。
- **分頁**：依高度裝，每頁的內容高度以 5 列 S 牆為上限。一段不拆開；單獨一段就超過一頁時才拆，續頁的標題加「（續）」。
- 抽數色塊顯示的是保底位置（`count`）。它跨版本累計，所以某個版本很早就出現高抽數的色塊是正常的。
- **只有匯入紀錄的帳號**：改用封存紀錄裡的卡池分段，標題是版本和 UP 名稱，可以多顯示該期抽數；對不上卡池的紀錄歸到最後的「未分類」。

### 保底週期

邏輯不動（`buildPityCycles`、`cycleTrackCells`），只把外框換成新風格：左側海報面板、上方狀態區，下面每頁 10 列週期。UP 的 S 在抽數旁加 UP 角標。保留 S／A／B 圖例。

## 角標、顏色、數字

- **UP 角標**：`isUp === true` 的 S 才畫。黃底 `#ffd21f`、墨色字和墨色外框的圓角小標，寫「UP」。取代現在的 TOP 圖示（`icon-top.140345aa.png`），圖檔和相關函式刪除。
- **抽數色塊**：實色膠囊加白色數字。顏色依抽數佔硬保底的比例：84% 以上 `#d9473b`、58% 以上 `#c9870f`、其餘 `#2f8f6f`。琥珀色比現在的 `#d99a1e` 深，白字才讀得到。
- **目前墊抽只有一個來源**：墊抽卡、S 牆的「?」格、保底週期的進行中那一列，在看頻道最新紀錄時一律用 `summary.currentPity`。

## 統計

官方綁定的帳號直接用新 API 的數字，這樣和官方工具對得起來：

| 畫面上的格子 | 來源 |
|---|---|
| 總抽數 | `total_count` |
| 平均出 S | `total_count` 扣掉目前墊抽後除以 `s_count` |
| UP / S | `up_count` / `s_count` |
| 每個 UP 平均 | `avr_up_count` |
| 目前墊抽 | `next_s_cur_times` |
| 距硬保底 | `new_s_max_times` |
| 硬保底 | 上面兩者相加 |
| S 數量（常駐、邦布） | `s_count` |

這些對應都用真帳號驗證過。常駐頻道沒有 UP 的概念，邦布頻道每個 S 都算 UP，這兩個頻道不畫 UP 角標，也不顯示「UP / S」和「每個 UP 平均」。

只有匯入紀錄的帳號用封存紀錄算。`GachaSummary` 新增欄位，現有欄位不動：

| 新欄位 | 意思 |
|---|---|
| `upWins` | 選定範圍內 `isUp === true` 的 S 數量 |
| `upEligible` | 選定範圍內 `isUp` 是 true 或 false 的 S 數量 |
| `averageUpCost` | 選定範圍內各個 UP S 的 `pullsSincePreviousUp` 平均，四捨五入到整數；沒有可算的就是 null |

- 「UP / S」顯示成 `upWins/upEligible`，取代原本的不歪率百分比。寫成分數是為了讓玩家看得出怎麼算的。
- 「每個 UP 平均」顯示 `averageUpCost`。它包含中間歪掉的抽數。頻道裡第一個 UP 沒有前一個 UP 可以對照，不列入平均。
- 「平均 UP 抽數」和「不歪率」兩格拿掉。`winRate`、`averageUp` 欄位留著不刪，其他地方沒用到的字串才清。

## 出錯和空資料

- 任何圖片載入失敗都當成沒有圖，走退回順序，不丟錯。

- 文字過長時縮小字級，再不行就截斷加省略號，不超出卡片。
